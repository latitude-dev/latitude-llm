## Overview

Cloudflare Think is built on the Vercel AI SDK. Think owns the internal
`streamText` call, so enable Latitude telemetry from the `beforeTurn` hook
instead of passing `experimental_telemetry` at a direct model call site.

Use the quick setup first. Add capture lifecycle hooks only when you want to
attach user ids, session ids, tags, metadata, or per-turn project routing.

<Note>
  This guide targets Think versions whose `TurnConfig` accepts
  `experimental_telemetry`. If your installed Think version does not expose this
  field, update `@cloudflare/think`.
</Note>

---

## Requirements

- A **Latitude account** and **API key**
- A **Latitude project slug**
- A Cloudflare Workers project using `@cloudflare/think`
- The `nodejs_compat` compatibility flag enabled in your Worker
- `LATITUDE_API_KEY` and `LATITUDE_PROJECT_SLUG` configured as Worker secrets or variables

## Quick Start

This is the fastest way to see Think model calls in Latitude. It does not use
`capture`; AI SDK telemetry creates the spans.

<Steps>

  <Step title="Install">
    <CodeGroup>
      ```bash npm
      npm install @latitude-data/telemetry
      ```

      ```bash pnpm
      pnpm add @latitude-data/telemetry
      ```

      ```bash yarn
      yarn add @latitude-data/telemetry
      ```

      ```bash bun
      bun add @latitude-data/telemetry
      ```
    </CodeGroup>
  </Step>

  <Step title="Initialize Latitude once">
    Create the Latitude instance lazily from the Worker environment. Then return
    `experimental_telemetry` from `beforeTurn` with a Latitude-owned tracer so
    Think forwards it to the AI SDK.

    ```ts
    import { Think, type TurnConfig } from "@cloudflare/think"
    import { Latitude } from "@latitude-data/telemetry"
    import { routeAgentRequest } from "agents"
    import { createWorkersAI } from "workers-ai-provider"

    type Env = {
      AI: Ai
      LATITUDE_API_KEY: string
      LATITUDE_PROJECT_SLUG: string
    }

    let latitude: Latitude | undefined

    function getLatitude(env: Env) {
      latitude ??= new Latitude({
        apiKey: env.LATITUDE_API_KEY,
        project: env.LATITUDE_PROJECT_SLUG,
        serviceName: "cloudflare-think-agent",
      })

      return latitude
    }

    export class MyAgent extends Think<Env> {
      getModel() {
        return createWorkersAI({ binding: this.env.AI })("@cf/meta/llama-4-scout-17b-16e-instruct")
      }

      beforeTurn(): TurnConfig {
        const latitude = getLatitude(this.env)

        return {
          experimental_telemetry: {
            isEnabled: true,
            tracer: latitude.getAiSdkTracer(),
            functionId: "think-turn",
            metadata: { framework: "cloudflare-think" },
          },
        }
      }
    }

    export default {
      async fetch(request: Request, env: Env, ctx: ExecutionContext) {
        const latitude = getLatitude(env)
        const response =
          (await routeAgentRequest(request, env)) ??
          new Response("Not found", { status: 404 })

        ctx.waitUntil(latitude.flush())

        return response
      },
    } satisfies ExportedHandler<Env>
    ```
  </Step>

</Steps>

## Add Capture Context

Use `capture()` when you want each Think turn to carry Latitude context such as
`userId`, `sessionId`, `tags`, `metadata`, or a per-turn `project`. Capture does
not create AI SDK spans by itself; keep `latitude.getAiSdkTracer()` in
`beforeTurn`.

<Warning>
  Do not use the `capture.start()` / `scope.end()` lifecycle API on Cloudflare
  Workers. It relies on `AsyncLocalStorage.enterWith()`, which the Workers runtime
  [does not implement](https://developers.cloudflare.com/workers/runtime-apis/nodejs/asynclocalstorage/)
  and which throws at runtime. Use the callback form shown below — it relies on
  `AsyncLocalStorage.run()`, which Workers does support.
</Warning>

Wrap the whole turn with the callback form of `capture()` before calling
`super.runTurn()`. Think runs `beforeTurn` and the model call inside
`super.runTurn`, so the AI SDK spans land under the active Latitude context:

```ts
import {
  Think,
  type RunTurnOptions,
  type RunTurnStream,
  type RunTurnSubmit,
  type RunTurnWait,
  type SubmitMessagesResult,
  type TurnConfig,
  type TurnResult,
} from "@cloudflare/think"
import { capture } from "@latitude-data/telemetry"

function stringFromBody(body: Record<string, unknown> | undefined, key: string) {
  const value = body?.[key]
  return typeof value === "string" && value.length > 0 ? value : undefined
}

export class MyAgent extends Think<Env> {
  beforeTurn(): TurnConfig {
    return {
      experimental_telemetry: {
        isEnabled: true,
        tracer: getLatitude(this.env).getAiSdkTracer(),
        functionId: "think-turn",
        metadata: { framework: "cloudflare-think" },
      },
    }
  }

  runTurn(options: RunTurnWait): Promise<TurnResult>
  runTurn(options: RunTurnSubmit): Promise<SubmitMessagesResult>
  runTurn(options: RunTurnStream): Promise<void>
  runTurn(options: RunTurnOptions): Promise<TurnResult | SubmitMessagesResult | void> {
    const body = "body" in options ? options.body : undefined
    const runParent = () =>
      (super.runTurn as (opts: RunTurnOptions) => Promise<TurnResult | SubmitMessagesResult | void>)(options)

    return Promise.resolve(
      capture("cloudflare-think-turn", runParent, {
        userId: stringFromBody(body, "userId"),
        sessionId: stringFromBody(body, "sessionId"),
        tags: ["cloudflare-think"],
        metadata: { continuation: "continuation" in options ? Boolean(options.continuation) : false },
      }),
    )
  }
}
```

<Note>
  `userId`/`sessionId` are read from the `options.body` passed to your
  wrapper/override before calling `super.runTurn()`. Do not rely on
  `beforeTurn(ctx.body)` for normal programmatic `wait` turns; current Think
  versions accept `body` on `runTurn()` but do not forward it into `beforeTurn`
  on that path.
</Note>

## Runnable Example

The Latitude repository includes a runnable Think example at
[`examples/cloudflare-think-app`](https://github.com/latitude-dev/latitude-llm/tree/development/packages/telemetry/typescript/examples/cloudflare-think-app).
It includes a
Worker entrypoint with a `getWeather` tool and a local verifier that sends a
deterministic Think-like AI SDK turn to `http://localhost:3002`, flushes
Latitude, and polls ClickHouse until both the model spans and the `ai.toolCall`
span arrive.

## Seeing Your Traces

Once connected, traces appear automatically in Latitude:

1. Open your **project** in the Latitude dashboard
2. Send a message to your Think agent
3. The turn appears with the model call, input/output messages, latency, token usage, and errors
