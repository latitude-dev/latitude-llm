<Info>
  **Where this fits:** This is the **Test and Fix** stage of the Latitude loop — after
  [Issue Discovery](../issues/overview), before the loop repeats with new production traffic.
  Here you act on what you found and make sure it stays fixed.
</Info>

Once you have a tracked [issue](../getting-started/concepts), Test and Fix is where you close the loop: connect Latitude to your coding agent, reproduce the failure, change your agent, and turn the failing traces into a regression test so the problem cannot quietly return.

## The fix-and-verify workflow

<Steps>
  <Step title="Bring the issue into your code">
    Connect your coding agent to Latitude with the [MCP server](../getting-started/mcp). Your agent
    can then read the failing [issue](../issues/overview), inspect example traces, and propose a fix
    in the same session.
  </Step>
  <Step title="Capture the failing traces as a dataset">
    Turn the traces behind an issue into a [Dataset](../datasets/overview) — a versioned set of
    inputs you can replay. This is the seed of a regression test.
  </Step>
  <Step title="Add the expected behaviour">
    Record what the agent *should* have done by [adding expected output](../datasets/expected-output)
    to the dataset rows, so a test can check against it.
  </Step>
  <Step title="Regression test the fix">
    Run your agent against the dataset and check the results with the same evaluations that monitor
    production. See [Regression testing](./regression-testing).
  </Step>
  <Step title="Resolve and keep monitoring">
    When the test passes, resolve the issue. The [Monitor](../monitors/overview) that watches the
    issue keeps checking live traffic, so a regression re-opens it automatically.
  </Step>
</Steps>

## Why test against real traces

Issues are discovered from real production failures, so the traces behind them are the most realistic test cases you have. Building datasets and regression tests directly from those traces means your tests cover the failure modes that actually happened — and the same evaluations that found the problem in production verify the fix.
