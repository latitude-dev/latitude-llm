<Info>
  **Where this fits:** Simulations are part of **Refine**. They take a [dataset](../datasets/overview) of real conversations, run your agent against those cases locally, and land the new sessions in Latitude so you can compare versions with [Experiments](../experiments/overview) and [Signals](../signals/overview).
</Info>

Latitude stores the examples and the results. Your agent runs in your own process, locally or in CI. Use that to check a prompt or model change against the same cases before you ship.

This guide uses [Scenario](https://github.com/langwatch/scenario) (Apache-2.0) as the simulation runner. It has TypeScript and Python SDKs and a user simulator for multi-turn conversations. The same pattern works with a plain loop for single-turn replay, or with another runner such as [promptfoo](https://www.promptfoo.dev/) or [Inspect](https://inspect.aisi.org.uk/).

## What a simulation is

You already have production traces in Latitude. A simulation replays those cases against a new version of the agent:

1. Curate a [dataset](../datasets/overview) from real traces, a signal, or a CSV.
2. Pull the rows with `@latitude-data/sdk` or `latitude-sdk`.
3. For each row, a simulated user talks to your agent. Single-turn rows replay the stored input. Multi-turn rows keep going until the task is done or you hit a turn limit.
4. [Telemetry](../telemetry/start-tracing) sends the new sessions to Latitude, tagged so you can tell them apart from production.
5. Compare the new sessions to a baseline with [Experiments](../experiments/overview). The same [evaluations](../evaluations/overview) that score production traffic can score the simulation traffic too.

The dataset, the SDK, and telemetry are the Latitude pieces. Scenario (or any other runner) is the piece that drives the conversation.

## Prepare a dataset

Build the dataset the way you already do for [regression testing](./regression-testing):

- From a [signal](../signals/overview), so the cases are the failures you care about. See [Add traces](../datasets/add-traces).
- From [Search](../search/overview) or a saved search, for a behavior you want to keep passing.
- By hand or CSV, for cases that never showed up in production.

Each row should have at least an **input**. That is the first user message, or a short description of what the user wants.

**Expected output** is optional and useful in two ways:

- As the known-good answer for a single-turn check.
- As judge criteria for a multi-turn run, for example "Issue the refund without asking for the order number twice."

Add a [custom column](../datasets/custom-columns) if you need extra fields such as a user persona or a tool the agent is allowed to call. Those values come back on `row.custom` from the SDK.

## Tag every simulated session

Give every simulation a `sessionId` of its own, and stamp the traces so you can filter them later.

| Field | Example | Why |
| --- | --- | --- |
| Tag `simulation` | `simulation` | Separates these sessions from production. |
| Tag for the agent version | `agent-v2` | Lets an experiment compare v1 vs v2. |
| Metadata `dataset` | `refund-regressions` | Ties the run back to the dataset slug. |
| Metadata `rowId` | the SDK `rowId` | Ties the session to one dataset row. |
| Metadata `agentVersion` | `v2` or a git SHA | The slice key for Experiments. |

Use a fresh `sessionId` per dataset row per run, for example `sim-${runId}-${rowId}`. All turns of that conversation share it, so they group as one [session](../observability/sessions).

If you already have [evaluations](../evaluations/overview) on the project, they will score simulation traces the same way they score production, unless their [triggers](../evaluations/triggers) filter them out. Keep the `simulation` tag so you can exclude this traffic from production monitors if you want to.

## TypeScript

Install the Latitude API SDK, telemetry, and Scenario:

```bash
npm install @latitude-data/sdk @latitude-data/telemetry @langwatch/scenario openai
```

Set `LATITUDE_API_KEY`, `LATITUDE_PROJECT_SLUG`, and whatever key your agent (and Scenario's user simulator) need, such as `OPENAI_API_KEY`. `AGENT_VERSION` is optional; default it to `local` when you run on a laptop.

Replace `runSupportAgent` with a call into your own agent. Instrument the same LLM SDK that agent uses. The example uses OpenAI, matching the [TypeScript SDK](../telemetry/typescript) setup.

```ts
import { randomUUID } from "node:crypto"

import { LatitudeClient } from "@latitude-data/sdk"
import { Latitude, capture } from "@latitude-data/telemetry"
import { createOpenAIInstrumentation } from "@latitude-data/telemetry/instrumentations/openai"
import scenario, {
  type AgentAdapter,
  AgentRole,
  judgeAgent,
  userSimulatorAgent,
} from "@langwatch/scenario"
import OpenAI from "openai"

const PROJECT = process.env.LATITUDE_PROJECT_SLUG!
const DATASET = process.env.LATITUDE_DATASET_SLUG!
const AGENT_VERSION = process.env.AGENT_VERSION ?? "local"
const RUN_ID = process.env.SIMULATION_RUN_ID ?? randomUUID()

const latitude = new Latitude({
  apiKey: process.env.LATITUDE_API_KEY!,
  project: PROJECT,
  instrumentations: [createOpenAIInstrumentation(OpenAI)],
})

const client = new LatitudeClient({
  apiKey: process.env.LATITUDE_API_KEY!,
})

function asText(value: unknown): string | undefined {
  if (value == null) return undefined
  if (typeof value === "string") return value
  return JSON.stringify(value)
}

async function loadAllRows(datasetSlug: string) {
  const rows = []
  let cursor: string | undefined

  for (;;) {
    const page = await client.datasets.listRows(PROJECT, datasetSlug, {
      cursor,
      limit: 200,
    })
    rows.push(...page.items)
    if (!page.hasMore || page.nextCursor == null) break
    cursor = page.nextCursor
  }

  return rows
}

function agentForRow(row: { rowId: string }): AgentAdapter {
  const sessionId = `sim-${RUN_ID}-${row.rowId}`
  return {
    role: AgentRole.AGENT,
    call: async (input) => {
      return capture(
        "simulated-agent-turn",
        async () => runSupportAgent(input.messages),
        {
          sessionId,
          tags: ["simulation", `agent-${AGENT_VERSION}`],
          metadata: {
            dataset: DATASET,
            rowId: row.rowId,
            agentVersion: AGENT_VERSION,
            runId: RUN_ID,
          },
        },
      )
    },
  }
}

async function simulateRow(row: Awaited<ReturnType<typeof loadAllRows>>[number]) {
  const input = asText(row.input)
  if (!input) return

  const sessionId = `sim-${RUN_ID}-${row.rowId}`
  const expected = asText(row.expectedOutput)
  const agents: AgentAdapter[] = [
    agentForRow(row),
    userSimulatorAgent(),
  ]
  if (expected) {
    agents.push(judgeAgent({ criteria: [expected] }))
  }

  const result = await scenario.run({
    name: `dataset row ${row.rowId}`,
    description: input,
    agents,
    threadId: sessionId,
    maxTurns: 8,
    script: [
      scenario.user(input),
      scenario.agent(),
      scenario.user(),
      scenario.agent(),
      expected ? scenario.judge() : scenario.succeed(),
    ],
  })

  if (!result.success) {
    console.error(`row ${row.rowId} failed: ${result.reasoning}`)
  }

  return result
}

await latitude.ready

try {
  const rows = await loadAllRows(DATASET)
  const results = []
  for (const row of rows) {
    results.push(await simulateRow(row))
  }

  const failed = results.filter((result) => result && !result.success).length
  console.log(`ran ${rows.length} rows, ${failed} failed`)
  if (failed > 0) process.exitCode = 1
} finally {
  await latitude.flush()
  await latitude.shutdown()
}
```

`capture()` has to wrap the actual agent call, not a value you already computed. Scenario's user simulator and judge typically use their own model client, so they will not show up in Latitude unless you instrument that client too.

`runSupportAgent` should accept the conversation so far (`input.messages`) and return the next assistant message. If your agent is stateful, key that state off Scenario's `input.threadId` and use the same id as `sessionId`.

## Python

Install the Latitude API SDK, telemetry, and Scenario:

```bash
pip install latitude-sdk latitude-telemetry langwatch-scenario openai
```

The same env vars apply. Use `AsyncLatitudeClient` so the dataset fetch can sit next to Scenario's async `run()`. Replace `run_support_agent` with a call into your own agent.

```python
import asyncio
import os
import uuid

import openai
import scenario
from latitude_sdk import AsyncLatitudeClient
from latitude_telemetry import Latitude, capture

PROJECT = os.environ["LATITUDE_PROJECT_SLUG"]
DATASET = os.environ["LATITUDE_DATASET_SLUG"]
AGENT_VERSION = os.environ.get("AGENT_VERSION", "local")
RUN_ID = os.environ.get("SIMULATION_RUN_ID", str(uuid.uuid4()))

latitude = Latitude(
    api_key=os.environ["LATITUDE_API_KEY"],
    project=PROJECT,
    instrumentations={"openai": openai},
)
client = AsyncLatitudeClient(api_key=os.environ["LATITUDE_API_KEY"])

scenario.configure(default_model="openai/gpt-4.1-mini")


def as_text(value):
    if value is None:
        return None
    if isinstance(value, str):
        return value
    return str(value)


async def load_all_rows(dataset_slug: str):
    rows = []
    cursor = None
    while True:
        page = await client.datasets.list_rows(
            PROJECT,
            dataset_slug,
            cursor=cursor,
            limit=200,
        )
        rows.extend(page.items)
        if not page.has_more or page.next_cursor is None:
            break
        cursor = page.next_cursor
    return rows


def agent_for_row(row):
    session_id = f"sim-{RUN_ID}-{row.row_id}"

    class DatasetAgent(scenario.AgentAdapter):
        async def call(self, input: scenario.AgentInput) -> scenario.AgentReturnTypes:
            async def run():
                return await run_support_agent(input.messages)

            return await capture(
                "simulated-agent-turn",
                run,
                {
                    "session_id": session_id,
                    "tags": ["simulation", f"agent-{AGENT_VERSION}"],
                    "metadata": {
                        "dataset": DATASET,
                        "rowId": row.row_id,
                        "agentVersion": AGENT_VERSION,
                        "runId": RUN_ID,
                    },
                },
            )

    return DatasetAgent()


async def simulate_row(row):
    input_text = as_text(row.input)
    if not input_text:
        return None

    expected = as_text(row.expected_output)
    session_id = f"sim-{RUN_ID}-{row.row_id}"
    agents = [
        agent_for_row(row),
        scenario.UserSimulatorAgent(),
    ]
    if expected:
        agents.append(scenario.JudgeAgent(criteria=[expected]))

    result = await scenario.run(
        name=f"dataset row {row.row_id}",
        description=input_text,
        agents=agents,
        thread_id=session_id,
        max_turns=8,
        script=[
            scenario.user(input_text),
            scenario.agent(),
            scenario.user(),
            scenario.agent(),
            scenario.judge() if expected else scenario.succeed(),
        ],
    )

    if not result.success:
        print(f"row {row.row_id} failed: {result.reasoning}")

    return result


async def main():
    try:
        rows = await load_all_rows(DATASET)
        results = [await simulate_row(row) for row in rows]
        failed = sum(1 for result in results if result is not None and not result.success)
        print(f"ran {len(rows)} rows, {failed} failed")
        if failed:
            raise SystemExit(1)
    finally:
        latitude.flush()
        latitude.shutdown()


if __name__ == "__main__":
    asyncio.run(main())
```

Python `capture()` accepts an async function; `await` it inside the adapter. Call `latitude.flush()` before the process exits, the same as any other short-lived [telemetry](../telemetry/python) script.

## Compare the runs in Latitude

After a run, open **Sessions** and filter on the `simulation` tag. Each dataset row should be one session. Turns, tool calls, cost, and errors look the same as production because they came through the same telemetry SDK.

To see whether a change helped:

1. Run the dataset once against the current agent (`AGENT_VERSION=v1`).
2. Make the change.
3. Run it again (`AGENT_VERSION=v2`).
4. Open [Experiments](../experiments/overview) and create two variants:
   - Baseline: tag `simulation` and metadata `agentVersion = v1`
   - Comparison: tag `simulation` and metadata `agentVersion = v2`

The experiment will compare session counts, cost, errors, tools, signals, and behaviors on those two slices. If a [signal](../signals/overview) you care about still fires on the v2 slice, the fix did not cover that case.

You can also search for `metadata.rowId` to inspect one case across versions.

## Gate it in CI

The scripts above already exit non-zero when Scenario's judge fails a row. Wire that into CI:

- Export the dataset, or keep reading it live with the SDK (the examples do the latter).
- Set `AGENT_VERSION` to the git SHA so experiments stay attributable.
- Set `SIMULATION_RUN_ID` to the CI run id.
- Fail the job when any row fails, or when a [score](../scores/overview) from your production evaluations drops below the bar you already use.

Single-turn CI that only checks expected output, without a user simulator, is covered in [Regression testing](./regression-testing).

## Single-turn without Scenario

If the dataset is one input and one expected output per row, you do not need a user simulator. Pull the rows, call the agent once, wrap that call in `capture()`, and check the output in your own test. The tagging convention and the Experiments comparison stay the same.
